Can you clarify why Raft requires a strict quorum for committing log entries, and what happens if a network partition isolates 2 nodes out of 5?

auto_awesome
LearnMate Tutor 10:43 AM Referenced: Ongaro §5.3, §5.4

In a cluster of N = 5 nodes, Raft enforces that any state machine transition requires agreement from a strict majority—defined mathematically by the pigeonhole principle:

Quorum Size = ⌊N / 2⌋ + 1 = ⌊5 / 2⌋ + 1 = 3 Nodes Strict Majority Requirement

When a network partition bifurcates the cluster into a Majority Partition (3 nodes) and a Minority Partition (2 nodes), split-brain is fundamentally prevented because the minority side can never satisfy the quorum equation.

Partition Topology (3-Node vs 2-Node Split) Safe State Guaranteed
Implementation: Quorum Commitment Check (Go) raft/server.go 
func (rf *Raft) checkCommitQuorum(entryIndex int) bool {
    matchCount := 1 // Self vote from leader
    quorumSize := (len(rf.peers) / 2) + 1

    for peerID, matchIdx := range rf.matchIndex {
        if peerID != rf.me && matchIdx >= entryIndex {
            matchCount++
        }
    }

    // Safety Guard: Cannot commit log entries from previous terms directly
    if matchCount >= quorumSize && rf.log[entryIndex].Term == rf.currentTerm {
        rf.commitIndex = entryIndex
        rf.applyCond.Broadcast() // Notify state machine
        return true
    }
    return false
}
